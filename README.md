# 店舗管理アプリ

店の売上・経費・在庫・予約・レジをまとめて見るためのアプリ。
いまはホーム画面だけができている。タイルを押しても中身はまだ無く、
「これから作ります」と出る。

## 画面

- ホーム … 8つのタイル（集計／経費／収支表／在庫管理／シフト管理／発注／エクスポート／設定）
- `settings/` … スタッフ名簿（時給つき）と商品リスト。名簿はシフト管理と同じ
  `shiftadmin.v1` を見ているので、どちらで直しても同じものが変わる。商品は `storeitems.v1`。
- シフト管理だけは別アプリ（github.com/keiki-takemoto/shift）の管理者ページに飛ぶ。
  `TILES` に `url` があるタイルはリンクになる。
- 携帯で見る前提。2列固定で、広い画面では中央に寄せる。

## 中身があるもの

- `shift/` … シフト管理（店長用）。3つのタブ。
  - **① 届いた希望** … 月カレンダーだけ。「その日に出られる人」を色つきの名前＋AM/PMで並べる。
    人ごとの一覧は置かない（竹本さんの指示）。月の行の右に「提出 n／m人」、
    スタッフのメモがあればカレンダーの下に出す。つないでいれば1分ごとに自動で増える。
  - **② 確定シフト** … ①と同じ書式の月カレンダー。決めた人が太字の色つきで並ぶ。
    候補のボタンを押して割り当て。上の行は「休業日を決める」と「確定」の2つだけ。
    **確定**＝その月のシフトをスタッフのページ（確定シフト）に反映する。押し直せば上書き。
    LINE文のコピー・CSV・印刷はやめた（竹本さんの指示）。
    下は人ごとの集計（出せる日／入った日／外れた日。休業日は除く）。
    マスの右上にバッジは置かない（竹本さんの指示）。日ごとの必要人数は**日付の数字を押す**と変えられる。
  - カレンダーの描画は `buildMonth(mode)` 1つで、mode が "req" と "shift" の違いだけ。
    休業日は大きな off、祝日は ★ つきのラベル、今日は赤丸。背景は白に固定（`data-theme="light"`）。
    **画面が狭くても7列のまま**（月全体が常に見えるように、竹本さんの指示）。
    文字やマス目の大きさは `clamp()` で画面幅に合わせて縮む。日ごとの縦並びには**しない**。
    「森川 AM」は**必ず1行**。入りきらないときは `fitNames()` がカレンダー全体の文字を
    収まるまで縮める（マスごとに変えるとちぐはぐになるので、1枚で1つの大きさ）。
    カレンダー内の時間は `13:00-17:00` → `13-17` と短く出す（LINE文やCSVは元のまま）。
  - **③ 設定** … 接続／スタッフ／スタッフに配るURLと文面／バックアップ。
    **LINEの文章から取り込む機能は削除した**（竹本さんの指示）。スタッフの希望はSupabase経由だけ。
    書式のコード（`shared/shift-format.js` の buildRequestText / parseRequests）は
    申請者ページの確認表示に使うので残してあるが、取り込みには使っていない。
    必要人数の曜日ごとの設定は置かない（竹本さんの指示で削除）。必要人数は全日2が既定で、
    ②のカレンダーで日付の数字を押せばその日だけ変えられる。
    毎週の定休日は②の「休業日を決める」を押すと出る曜日ボタンで決める（全月に効く）。
    個別の日はマスを押す（その月だけ）。
  もとは shift リポジトリの `admin/` にあったものを引っ越した。
  - `shared/` の3ファイル（theme.css / shift-format.js / sync.js）は
    スタッフ用アプリ（github.com/keiki-takemoto/shift）と**同じものを両方に置いてある**。
    書式や通信を直すときは両方直すこと。
  - スタッフが希望を出すページは別アプリのまま（https://keiki-takemoto.github.io/shift/ ）。
    その場所は `shift/index.html` の `STAFF_APP` に書いてある。
  - **置き場所は Supabase**（2026-09-19にGoogleスプレッドシート＋Apps Scriptから移行）。
    SQLは `server/supabase.sql`、手順ページは `shift/setup.html`。
    表はRLSで全部拒否し、SQLで作った5つの関数（shift_ping / shift_submit_request /
    shift_list_requests / shift_publish / shift_get）だけが中身に触れる。
    合言葉は関数の中で確かめるので、anonキーがスタッフのURLに入っていても中身は守られる。
    サーバー側のコードを置かずに済むぶん、Apps Scriptより設定が短い。


- `cost/` … 経費（店長用）。3つのタブ。2026-10-15 にみつ澤アプリから移植。
  - **変動費** … 日付・科目（飲食店用15種：食材費F／食材費D／消耗品費…雑費）・支払い方法
    （Card払い／PayPay／現金／その他）・金額・メモ。下に月の合計・科目別・明細（🗑で削除）。
  - **固定費** … 名称・月額・支払い方法・メモ。行を押すと下から編集画面が出る。
    月額は**どの月にもそのまま**入る（途中で金額を変えると過去の月も変わる。竹本さんの指示でみつ澤と同じ）。
  - **人件費** … ◀日付▶で日を選び、スタッフごとに始まり・終わりの時刻と交通費を入れる。
    お給料＝働いた時間×名簿の時給＋交通費。**深夜割増は無し**（竹本さんの指示）。
    終わり≦始まりなら日をまたいだとみなす。確定シフトに入っている人を上に出し、
    シフトが「13:00-17:00」のような時刻なら「シフトの時刻を入れる」ボタンが出る。
    **入れた時点の時給を記録に残す**（名簿は端末の中だけにあるのと、時給を変えても過去の分を変えないため）。
- `pl/` … 収支表（店長用）。月別／年間。売上・人件費・変動費・固定費・FL比率・営業利益。
  - FL比率＝（食材費F＋食材費D＋人件費）÷売上。60%以下 良好／70%超 要改善。
  - 年間の固定費は「月額×記録のあった月の数」（みつ澤と同じ考え方。売上の代わりに経費・人件費のある月も数える）。
  - **売上はまだ未接続**。売上は `shared/sales.js` の `Sales.get(from,to)` だけから受け取る。
    レジ機能を作ったら、その中身を書き換えれば収支表がつながる（収支表の側は直さなくてよい）。
- `stock/` … 在庫管理（店長用）。2026-11-01 追加。
  - 上の月バーで月を選ぶ（直近6か月を一度に受け取って、その中から切り出すだけ）。
  - **月次の販売報告** … 「月次の報告が必要」の印を付けた商品を、カテゴリーがちがっても
    ここにまとめて出す。売れた数・売上・残り。売れていない商品も報告のために残す。
    「この月の報告をコピー」でタブ区切りの文字にして写す（メールにも表計算にも貼れる）。
    委託販売の月次報告のための画面。
  - **カテゴリーごとの在庫** … カテゴリーを押すと中の商品が出る（`<details>`）。
  - 商品リストは**見るだけ**。設定や発注が持っているものを書きかえない。
  - 「月次の報告が必要」の印は、**商品の表ではなく `store_meta` の `rep`**（商品idの配列）に入れている。
    `store_items` に列を足すと Supabase のSQLを入れ直してもらう必要があるため。
    入れるのは設定 → 商品（`metaPut("rep", [...])`）、在庫管理は読むだけ。
    ひとつの印を2つの端末で同時に変えると、あとに送ったほうが残る。
- `shared/receipt.js` … レシートを紙に出す部品。レジの「会計のあと」と、設定 → レジ → レシート が使う。
  - **Bluetoothのプリンタは繋げない。** iPad・iPhone の Safari / Chrome には
    Web Bluetooth が無く、Apple がこれを入れない方針のため（2026年11月時点で変わらず）。
    Android の Chrome やパソコンなら繋げるが、店はiPadなのでその道は取っていない。
  - かわりに `window.print()` で端末の「プリント」に渡す。
    **Wi-Fi（AirPrint）対応のレシートプリンタ**ならこれで出る。
    ふつうのプリンタでもPDFでも同じものが出る。
  - 印刷のときだけ `body > *` を隠して、`body` の直下に足した `#__rcpt` だけを出す。
    レジの画面は `html,body{overflow:hidden;height:100%}` で固めてあるので、そこも戻している。
  - 紙の幅は 80mm（印字 72mm）と 58mm（印字 48mm）。
  - 店名・住所・登録番号・消費税・紙の幅・下のひとことは、
    **高単価のラインと同じ `store_meta` の `"reg"`（REGSET）の中の `rc`**。
    ここもSQLを触らずに済ませている。
  - 登録番号を入れたときだけ「◯%対象」と「内 消費税」を出す（適格簡易請求書の形）。
    **軽減税率（8%）には対応していない**。商品ごとに税率を持たせるところからになる。
  - お預かり・お釣りはレシートに出すだけのもので、`sale.cash` に置いて**置き場所には送らない**
    （`flush()` が送る項目の並びに入れていない）。
  - **軽減税率（8%）** … 飲み物など。商品ごとに 設定 → 商品 で「8%」の印を付ける。
    印の置き場所は **`store_meta` の `tax8`**（商品idの配列）。`rep` とまったく同じやり方で、
    `store_items` に列を足さずに済ませている。書くのは設定だけ、レジは読むだけ。
    **レジは会計のときに、その行の税率を `line.tx` に焼きつける**（10 か 8 の数字）。
    あとから印を変えても、昔のレシートや記録は変わらない。`tx` は `lines` の中なので
    Supabaseにもそのまま乗る（SQLの変更は不要）。
    `tx` の無い古い会計は、ふつうの税率として扱う。
    レシートは税率ごとに「◯%対象」と「内 消費税」を出し、軽減のものには明細に ※ を付ける。
    **値引きは税率ごとの売上の割合で按分**してから消費税を出す
    （端数は税率の低いほうで調整するので、税率別の合計の和は必ず会計の合計と一致する）。
  - **ガワのアプリ（`../store-ios`）の中で開いたときは、Bluetoothのプリンタに出す。**
    `window.ZipangShell` があるかどうかで `print()` が行き先を変える。
    渡すのは「行の並び」（`doc()` が作る）で、HTMLではない。
    機種が変わってもHTMLを直さずに済むように、紙の組み立ては Swift 側に寄せてある。
    `print()` は Promise を返す。失敗の文句（紙切れ、Bluetoothが切れている等）は
    Swift 側が日本語で返すので、そのまま画面に出している。
- `shared/books.js` … 経費・人件費の置き場所。端末の中（`storebooks.v1`）と Supabase の `store_books`。
  関数は `store_books_get` / `store_books_put` で、**店長用キーだけ**が通る（スタッフの合言葉では読めない）。

## これから作るとき

- タイルを増やす・名前を変えるのは `index.html` の `TILES` の並びだけ。
- 中身を作るときは `sales/`、`cost/` のようにフォルダを足し、TILESに `url` を持たせて飛ばす。
- 直したら `sw.js` の `CACHE = "store-v1"` の番号を1つ上げる。上げないと古い画面が端末に残る。
- アイコンは `python3 make_icons.py`。

## 置き場所（まだ決めていない）

売上など、貯めるデータの置き場所はまだ作っていない。
シフトアプリ（github.com/keiki-takemoto/shift）で使っている
Googleスプレッドシート＋Apps Script と同じやり方を流用できる。
